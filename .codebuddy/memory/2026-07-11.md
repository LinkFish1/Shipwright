## 编译成功（用户下令"编译"，含风之杖默认关全部 26 处改动）
- **关键坑：全局文件锁**。本环境里 `cmd /c "..."` 一旦带 `>`/`>>` 重定向就报 "The process cannot access the file because it is being used by another process"（中文"另一个程序正在使用此文件"）。根因是之前会话/本次用 `start /b`、`powershell Start-Process` 拉起的**分离 cmd/conhost 僵尸进程**持有了控制台/目录句柄（IDE 属主、Stop-Process 报"拒绝访问"杀不掉）。后果：所有 `.bat` 落地文件构建、所有 `cmd /c ">log"` 重定向构建全部失败；连 `echo X > C:\test123.txt` 都 "Access is denied"（C:\ 根无写权）。但**纯 `cmd /c "echo X"` 无重定向正常**、**powershell `>` 重定向正常**。
- **正解（本轮回绕过）**：`powershell -NoProfile -Command "& cmd.exe @('/c', 'MSBuild.exe <sln> /p:... /m /nologo /verbosity:minimal') 2>&1 | Out-File <log> -Encoding utf8"`。**cmd 内部不写 `>`**（stdout 交给 powershell 用 `| Out-File` 落盘），彻底避开 cmd 重定向锁。该命令成功跑完整构建。
- **正确 .sln 路径**：`build\x64\soh\soh.sln`（不是 `soh\soh.sln`！后者 MSBuild 报"项目文件不存在"）。VS 装在 **BuildTools 2022**：MSBuild 8.3 短路径 `C:\PROGRA~2\MIB055~1\2022\BUILDT~1\MSBuild\Current\Bin\MSBuild.exe`；vcvarsall `C:\PROGRA~2\MIB055~1\2022\BUILDT~1\VC\AUXILI~1\Build\VCVARS~1.BAT`。**实测 MSBuild 无需 vcvarsall 也能自定位工具集**（C++ 编译正常），所以可省去 vcvarsall。
