## 翻译乱码（"????"/"P???"）根因与修复（用户指令：发现很多翻译错误如????、P???，找到所有类似错误并解决）
- 用户看到的乱码是**豆腐块(tofu)**，不是表里的字面 "????" 字符串（搜 `\?{3,}` 全无匹配）。
- **根因 1（真正的乱码来源）**：翻译 VALUE 中用了 7 个**不在 `DroidSansFallback.ttf`（x64/Release 与 soh/soh/SohGui/fonts 两个都是 33275 码点）里的非 ASCII 字符，导致合并进 atlas 时渲染成 "?"：
  - `“` U+201C、`”` U+201D（弯引号，50×）
  - `—` U+2014（破折号，48×）
  - `…` U+2026（省略号，21×）
  - `·` U+00B7（中间点，28×）
  - `→` U+2192（箭头，4×）
  - `é` U+00E9（3×）
  - 用 fontTools 比对 gChineseTable 全部 4364 条 value 的码点 vs 字体 cmap，确认这 7 个 **全部缺失**，其余 1615 个非 ASCII 字符都在字体里（即无其他乱码源）。
- **修复 1**：只改 VALUE（KEY 不能改——它必须精确匹配运行时 C++ 字面量用于查表，且中文模式下不显示 KEY），把上述 7 字符替换为字体里存在的等价字符：
  - `“`→`「`(U+300C)、`”`→`」`(U+300D)（已验证在字体）
  - `—`→`--`、`…`→`...`、`·`→`・`(U+30FB)、`→`→`->`、`é`→`e`
  - 脚本逐行解析条目、仅变换 VALUE 中的这 7 字符，KEY/转义(`\n` `\"` `\\`)原样保留。
- **根因 2（英文而非中文显示）**：之前自动翻译把 `Option::Disable(text)` 的禁用原因写成了**错位碎片**（例如 key `"This option is disabled because \""` + `" are shuffled to \""` + `"."`），而运行时 `Disable()` 把相邻字符串字面量**拼接**成完整串（如 `This option is disabled because "Dungeon Rewards" are shuffled to "End of Dungeons".`），碎片 key 永远匹配不上 → 原因以英文显示。拼接规则：字面量直接相连、**不加空格**，保留 `\n` 与 `\"`。
- **修复 2**：把碎片合并为 7 条正确整键条目（已逐条比对 settings.cpp 的 Disable() 调用确认完整 key）：
  - Gerudo Fortress、Triforce（注意 "enabled." 与 "Ganon's" 间**无空格**）、Dungeon Rewards→End of Dungeons、Dungeon Rewards→Vanilla（此前整条缺失）、Loach、Force-enabled Ganon、Skip Child Zelda。
  - 这些条目须位于 `gChineseTable` 的 `};` **之前**（曾因脚本把 `};` 一并匹配导致整段被移到 `};` 之后、游离在 map 外，已纠正）。
- **排查结论**：`\\"` 双反斜杠不是真 bug——之前在 execute_command 输出里看到的 `\\"` 是 PowerShell CLIXML 对单反斜杠的显示转义；`CollectCodepoints`/`BuildCjkRanges` 的 UTF-8 解码与合并范围都对；`MergeSimplifiedChineseInto` 在 OTRGlobals.cpp 对 8 个字体正确调用。
- 修复后校验：VALUE 中缺失的非 ASCII 字符 = **0**；`Localization.cpp` lint = **0 诊断**。
